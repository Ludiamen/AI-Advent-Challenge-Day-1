# Day-1 — запрос к LLM через API

Минимальный проект: отправляет запрос в LLM (DeepSeek, `deepseek-v4-flash`),
получает ответ и выводит его в консоль (CLI) или в браузере (Web).

## Структура

| Файл | Назначение |
|------|------------|
| `llm_client.py` | Ядро: `ask()` / `ask_full()`, `PROFILES`, `FORMATS`, `LENGTH_PRESETS`, `build_structured_profile()` |
| `cli.py` | Консольный интерфейс, флаги `--profile` / `--format` / `--words`, справка в `--help` |
| `web.py` + `templates/index.html` | Веб-интерфейс на Flask: выбор профиля/формата/длины + блок «Справка по форме» |
| `compare.py` | Один запрос с двумя уровнями контроля + сравнение метрик |
| `.env.example` | Шаблон конфигурации; копируется в `.env` |

## Профили контроля ответа

| Профиль | Явный формат | Ограничение длины | Условие завершения |
|---------|--------------|-------------------|--------------------|
| `свободный` | нет | нет | нет |
| `строгий` | инструкция в промпте по выбранному формату (`--format`) | инструкция «не более N слов» (`--words`) + `max_tokens` как предохранитель | stop-последовательность `["END"]` + требование напечатать `END` |

Профиль `строгий` собирается под выбор пользователя функцией
`llm_client.build_structured_profile(fmt, words)`.

**Форматы** (`--format`, ключи `llm_client.FORMATS`):

| Ключ | Что получится |
|------|---------------|
| `список-3` | маркированный список ровно из 3 пунктов |
| `список-5` | маркированный список ровно из 5 пунктов |
| `шаги` | нумерованный список шагов |
| `абзац` | один связный абзац |
| `резюме` | одно предложение-резюме (TL;DR) |
| `вопрос-ответ` | 2–3 пары «Вопрос — Ответ» |

**Длина** (`--words`): пресеты 10 / 50 / 200 или любое своё число (1–2000).
В вебе выбор из выпадающего списка, поле «…или своё число слов» переопределяет пресет.

> `deepseek-v4-flash` — рассуждающая модель: скрытые reasoning-токены тоже расходуют
> `max_tokens`, поэтому кэп берётся с большим запасом (`≈ 900 + слова×6`), а реальную
> длину и форму ответа держит инструкция в промпте. `compare.py` и веб показывают,
> сколько токенов ушло на рассуждение (`reasoning=…`).

## Установка

```bash
# Ubuntu: команда называется python3 (пакеты python3 + python3-venv)
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env      # затем вписать свой ключ в .env
```

После `source .venv/bin/activate` внутри окружения доступна и команда `python`.
Без активации используйте `.venv/bin/python`.

## Запуск

### CLI

```bash
python cli.py "Привет! Кто ты?"
python cli.py --profile строгий --format список-5 --words 10  "Чем полезна ходьба?"
python cli.py --profile строгий --format абзац    --words 200 "Чем полезна ходьба?"
python cli.py --profile строгий --format резюме   --words 25  "Чем полезна ходьба?"
python cli.py                     # интерактивный режим (в диалоге «?» — памятка, Ctrl+C — выход)
```

Полная справка с описанием профилей, форматов и примерами — `python cli.py --help`.

Как это читать:
- без флагов — профиль `свободный`, ответ без ограничений;
- `--profile строгий` включает все три рычага сразу: `--format` задаёт структуру,
  `--words` — предельную длину, а `END` — момент остановки;
- `--format` и `--words` без `--profile строгий` игнорируются;
- в интерактивном режиме профиль/формат/длина задаются флагами один раз при запуске.

### Web

```bash
python web.py                     # http://127.0.0.1:5000
```

На странице: поле запроса и четыре селектора — **Профиль**, **Формат**, **Длина ответа**
(пресет) и поле **«…или своё число слов»** (переопределяет пресет). Под ответом —
метрики (`finish_reason`, число слов, токены, `reasoning`). Раскрывающийся блок
**«❓ Справка по форме»** внизу страницы описывает все поля и содержит примеры.

### Сравнение уровней контроля (один запрос — два профиля)

```bash
python compare.py                              # демо-запрос, строгий = список-3 / 50 слов
python compare.py "Свой вопрос"
python compare.py --format шаги --words 200 "Свой вопрос"
```

`compare.py` печатает оба ответа, `finish_reason`, число слов/символов и расход
токенов (включая reasoning) — видно, как `строгий` укорачивает и структурирует
ответ, а генерация завершается по stop-последовательности (`finish_reason=stop`).

## Безопасность

- Ключ читается только из переменной окружения `DEEPSEEK_API_KEY` (через `.env`),
  в коде его нет.
- `.env` внесён в `.gitignore` — реальный ключ не попадёт в git.
- В репозиторий коммитится только `.env.example` с плейсхолдером.
- У HTTP-запроса задан таймаут; ключ не логируется и не отображается в ошибках.
- Flask запускается на `127.0.0.1` с `debug=False` (без внешнего доступа и отладчика).
- Если ключ скомпрометирован — отзовите его в панели DeepSeek и выпустите новый.
